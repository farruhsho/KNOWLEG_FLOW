## 7. Что делает методист

**Правило двух лиц**: одобряет методист (роль `methodologist` или
`super_admin`), а не оператор пайплайна. Математику — учитель математики,
вербальный раздел, чтение и грамматику — учитель русского языка.

### Чек-лист (каждое из 150 заданий)

1. Решить самостоятельно, не глядя на ключ; ответ совпадает с
   `key.correct`.
2. Верный вариант ровно один, остальные однозначно неверны; нет «все/ни один
   из перечисленных», двойных отрицаний, ловушек в формулировке.
3. Дистракторы правдоподобны и соответствуют типичным ошибкам;
   `wrong_option_notes` описывают эти ошибки верно (ошибка именно такого
   рода найдена в раунде 2).
4. Объяснение и `solution_steps` верны, последовательны, понятны выпускнику.
5. Содержание в рамках школьной программы КР; `source.basis` (класс, тема),
   тема, подтема и сложность 1–3 размечены верно.
6. Русский язык — литературная норма (орфография, пунктуация, управление,
   «ё» там, где она нужна для понимания).
7. Формат части: сравнение величин — D («информации недостаточно») только
   когда соотношение действительно зависит от неизвестных; аналогии — тип
   отношения однозначен и пары не перевёрнуты в ключе; дополнение — пропуск
   «____»; чтение — ответ следует только из текста, факты в текстах верны
   (Хардин 1968, Нобелевская премия Остром 2009, снеговая линия Тянь-Шаня

8. Оригинальность: задание не похоже на известные задания ЦООМО/testing.kg,
   Secom, ORTPREP, сборников и сайтов; при сомнении — `rejected`.
9. Этичность: нет дискриминации, агитации, травмирующих сюжетов; имена и

10. Нет подсказок между заданиями варианта (особенно вербальный ↔

части, темы и сложности (для чтения — к тому же тексту), затем:

```bash
npm run cli -- lint --fix && npm run cli -- lint
npm run cli -- verify --local-only --max-items 1000
npm run cli -- dedup
npm run cli -- assemble --blueprint ort_main_2026 --language ru --numbers 1 --allow-unapproved   # пересобирает черновик v_..._001, content_version +1
```

После одобрения всех 150 заданий:

```bash
npm run cli -- validate --blueprint ort_main_2026 --language ru --publish   # должно быть 0 ошибок (останется предупреждение LANGUAGE_MISSING)
npm run cli -- import --blueprint ort_main_2026                             # DRY RUN: план в content/reports/import-plan.json, ничего не пишет
npm run cli -- import --blueprint ort_main_2026 --commit                    # запись в Firestore (knowleg-33f36): blueprint, 3 текста, 150 вопросов и ключей, вариант-черновик
```

Публикация: если варианта ещё нет в Firestore —
`npm run cli -- import --blueprint ort_main_2026 --publish --published-by <uid> --commit`;
если он уже импортирован черновиком — опубликовать в админке
(`adminPublishVariant`), затем `npm run cli -- review-sync --blueprint
ort_main_2026`.

Путь (а) — одобрение в админке: `import --blueprint ort_main_2026` (dry run),
затем `import --blueprint ort_main_2026 --commit` загружает задания со
статусом `ai_verified` и вариант-черновик; методист одобряет/отклоняет в
админке; `npm run cli -- review-sync --blueprint ort_main_2026` переносит
решения в банк; публикация — в админке. Правки текста в админке нужно
перенести в банк (иначе они попадут в `cms_conflicts` при следующем импорте).

`import --commit` требует учётных данных Firebase (Application Default
Credentials) и никогда ничего не удаляет.

## 8. Ограничения (честно)

* Все задания и тексты написаны ИИ и проверены ИИ (автор и верификаторы —
  разные агенты одной модели, поэтому их ошибки могут совпадать). Статус
  `ai_verified` — **не** одобрение методиста; без проверки человеком вариант
  нельзя публиковать в платном продукте.
* Кыргызская версия **не создана**. Blueprint `ort_main_2026` требует ru и
  ky; номер варианта 1 засчитается в реестре только когда будет одобрен на
  обоих языках (перевод — `generate --translate-from ru --language ky`, затем
  `translate-check` и методист — носитель кыргызского языка).
* Оригинальность проверена самоконтролем авторов, слепыми проверками и
  `dedup` только внутри банка; сравнения с существующими базами (`dedup
  --against` после `export-existing`) не было.
* Тайминг — модельная оценка, не замер; статистика сложности по реальным
  попыткам появится только после запуска.
* Причины замечаний раунда 1 сохранены только в журналах workflow; в 3
  заданиях (reading_a × 2, math_problems × 1) по файлам нельзя установить,
  какие именно задания правились.
* Дата проверки в заметках — 2026-11-05 (как задано workflow), `updated_at`
  — фактическое время записи.
* Ограничения пайплайна (код не менялся, передать владельцу):
  (1) `verify --local-only` по умолчанию берёт только первые 100 заданий по id
  (`--max-items 100`) — для полного прогона нужен `--max-items 1000`;
  (2) арифметический чекер (`src/arith.ts`) читает смешанные числа вида
  `1\frac{1}{2}` как произведение и даёт ложный FAIL, а платный `verify` из-за
  этого отклонит верное задание.
